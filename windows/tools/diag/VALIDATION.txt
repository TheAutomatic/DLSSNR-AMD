BLACKGATE DIAGNOSTIC / 黑屏诊断

DIAG7 FIX COMPARISON / DIAG7 修复对照

Use run_blackgate_fixes.bat [N] for this round (default 3 runs each).
It clears NR_DIAG_STAGE: all five modes run normal processing, not stage 2.
Order: baseline (NR_DIAG_FIX unset), device-nobda, device, robust, all.
Unset, empty or invalid NR_DIAG_FIX preserves the previous behavior.
device = legalize NR feature structs/extensions, enable supported shaderInt16,
         and follow logical-device BDA/subgroup enables. BDA may turn ON on x86.
device-nobda = device legalization with BDA structs/extensions removed.
robust = only use pipeline robustness overrides if logically enabled.
all = device-nobda + robust, deliberately retaining storage-buffer shaders.
Check NR_DIAG_FIX, extension/struct decisions and selected BDA shader-path banners.
If creation falls back to the original device or required features are missing,
NR may not run: do not count that as a successful fixed NR result.
ReShade can load the add-on during vkCreateInstance, too late to observe its
requested API version. If unknown, the banner says so and conservatively adds
supported parent extensions even for promoted features. It does not raise the
application API version or change the shader SPIR-V target.
Keep all other settings unchanged; remove NR_NO_BDA if testing device's BDA path.
Logs: logs\fix_<mode>_run<R>.log; results append to logs\results.txt.
Back up logs between rounds. Verify each copied log has the matching mode and
NR_DIAG_STAGE=0 banner; a failed launch can leave a stale source log.
Also report missing textures/models separately from a black 3D scene.

本轮请运行 run_blackgate_fixes.bat [N]，默认每种模式 3 次。
脚本清除 NR_DIAG_STAGE，按 baseline、device-nobda、device、robust、all
顺序运行正常处理。baseline 不设置 NR_DIAG_FIX；空值或无效值保持原行为。
device：修正功能结构与扩展启用，启用支持的 shaderInt16，并按逻辑设备
实际启用状态选择 BDA/子组大小控制；x86 可能转为 BDA 着色器路径。
device-nobda：同上但移除 BDA 结构和扩展；robust：仅在实际启用时使用
流水线健壮性覆盖；all：device-nobda 加 robust，保持存储缓冲区路径。
请检查模式、结构/扩展增删和 BDA 路径日志。若设备创建回退或缺少必要
功能导致 NR 未运行，不要算作修复成功。插件可能加载太晚而无法观察
请求的 API 版本；未知时会记录并保守添加支持的父扩展，不提高 API 版本，
也不更改 SPIR-V 目标。保持其他设置一致，测试 device 的 BDA 时移除
NR_NO_BDA。结果附加到 logs\results.txt，日志为 fix_<模式>_run<R>.log。
每轮先备份 logs；检查日志模式及阶段 0 标识，避免误用启动失败留下的旧日志。
请单独报告模型/材质缺失，不要只记录是否黑屏。

The older stage runner described below is optional; do not use it for this round.
以下旧阶段脚本仅供手动诊断，本轮不要使用。

Copy addon32 beside Game.exe, keeping your existing NR data and settings.
From that folder run run_blackgate_stages.bat [N] (default: 3 runs per stage).
Exit the game after observing the 3D scene; answer y only if the 3D scene is black.
This package runs stages 2, 5, 7 and 8 (3 runs each by default).
2 = build/prepare only; no per-frame NR recording or EffectRecording flush/fence.
5 = ReShade outer barriers plus NR raw image/global memory barriers; no copy/init.
7 = only ReShade render_target <-> copy_source barriers; no raw NR barriers.
8 = only raw NR image/global memory barriers; no ReShade outer barriers.
Before effects are available, stages 5/7 also retain the startup Present
fallback's PRESENT_SRC_KHR <-> COLOR_ATTACHMENT_OPTIMAL wrapper pair.
Stage 8 starts/restores COLOR_ATTACHMENT_OPTIMAL in effect callbacks, or
PRESENT_SRC_KHR in the startup Present fallback, without its wrapper barriers.
Stages 5/7/8 retain normal CPU/runtime setup, other stage/network allocations,
background upload submissions and EffectRecording flush/fence work. Thus stage 2
versus 5 is not solely a barrier comparison. While the network builds, the outer
pair can run before the raw diagnostic is ready. No stage here dispatches NR.
Stages 0-6 remain available manually. Stage 9 is SKIPPED: stock ReShade 6.8.0
already establishes COLOR_ATTACHMENT_OPTIMAL around effect callbacks; its
render_target conversion agrees. No definite incorrect layout was established.
The old "image-free network build" stage 7 was never implemented; 7 now means
outer barriers only. These stages do not fix or establish a black-screen cause.
Use fresh logs folders between sessions: stage<S>_run<R>.log files are overwritten;
results.txt is appended. Keep [Log] Enabled=1 and ClearOnStart=1 (the defaults).
NR logs beside the add-on module, not necessarily beside Game.exe. The supplied
Blackgate logs show the add-on in the game's Bin folder. If different, set
NR_LOG_PATH to the full path of dlssnr-amd.log before running the batch. Unwritable
module folders fall back to %LOCALAPPDATA%\DLSSNR-AMD\apps\<tag>\dlssnr-amd.log.
If the game exits before NR starts, an old log may remain; check its stage banner.

把 addon32 放到 Game.exe 旁，保留现有 NR 数据和设置。在该目录运行
run_blackgate_stages.bat [N]，默认每阶段 3 次。观察 3D 场景后退出游戏；
仅在 3D 场景变黑时回答 y。本包运行 2、5、7、8，每阶段默认 3 次。
2：仅构建/准备，不执行逐帧 NR 录制或 EffectRecording 提交/栅栏；
5：ReShade 外层屏障和 NR 原始图像/全局内存屏障，不初始化拷贝目标、不拷贝；
7：仅 ReShade 外层屏障；8：仅 NR 原始屏障，不执行 ReShade 外层屏障。
效果尚未就绪时，5/7 的 Present 回退仍保留 PRESENT_SRC_KHR 与
COLOR_ATTACHMENT_OPTIMAL 之间的包围屏障。
8 在效果回调中从 COLOR_ATTACHMENT_OPTIMAL 开始并恢复；启动时 Present
回退则从 PRESENT_SRC_KHR 开始并恢复，同时跳过该回退的包围屏障。
5/7/8 保留其余构建/分配、后台上传和 EffectRecording 提交/栅栏；所以
2 与 5 的差别不只是屏障。网络未就绪时外层屏障可能先于原始屏障执行。
0-6 仍可手动选用；9 跳过：上游 ReShade 6.8.0 的布局与现有外层屏障一致，
未发现确定的布局错误。之前未实现的“无图像构建”7 现在改为仅外层屏障。
这些阶段都不执行网络推理，也不代表已修复或确定黑屏原因。
日志在插件旁；目录不可写时转到上述 LOCALAPPDATA 路径。可用 NR_LOG_PATH
指定日志完整路径。每轮结果在 logs\results.txt，日志在 logs\stage<S>_run<R>.log。
换一批测试前备份 logs，避免覆盖。游戏若未启动到 NR，注意旧日志的阶段标识。

VALIDATION (one separate run, NR_DIAG_FIX=all, stage 0; do not use either batch)

Install a current Vulkan SDK with the 32-bit Khronos validation layer for this
32-bit game. The SDK's vkconfig can select Game.exe, enable
VK_LAYER_KHRONOS_validation, and enable Synchronization Validation. Keep core
validation enabled too (allocation/binding/handle errors). Set Debug Action to
Log Message and Log Filename to an absolute writable file, e.g.
C:\NRLogs\blackgate-validation.txt. Disable the vkconfig override afterwards.

Alternatively, with vkconfig overrides OFF, open cmd.exe in the game folder:
  mkdir C:\NRLogs
  set "NR_DIAG_STAGE=0"
  set "NR_DIAG_FIX=all"
  set "VK_INSTANCE_LAYERS=VK_LAYER_KHRONOS_validation"
  set "VK_LAYER_ENABLES=VK_VALIDATION_FEATURE_ENABLE_SYNCHRONIZATION_VALIDATION_EXT"
  set "VK_LAYER_VALIDATE_SYNC=true"
  set "VK_LAYER_DEBUG_ACTION=VK_DBG_LAYER_ACTION_LOG_MSG"
  set "VK_LAYER_LOG_FILENAME=C:\NRLogs\blackgate-validation.txt"
  Game.exe

For this all-mode run, confirm the missing-parent device feature VUIDs, BDA
allocation-flag VUID and pipelineRobustness 06926-06929/pNext VUIDs are gone.
Capture remaining errors too: ReShade descriptor indexing and SPIR-V-1.6 versus
Vulkan-1.1 errors are not repaired by these candidate fixes. Use a current x86
validation layer that understands VK_EXT_shader_float8, not SDK 1.3.296.
这次验证请单独设置 NR_DIAG_FIX=all、阶段 0，确认设备功能父扩展、BDA
分配标志及 pipelineRobustness 06926-06929/pNext 错误消失。其他错误也
请保留；ReShade 描述符索引及 SPIR-V 1.6/Vulkan 1.1 不匹配不在本次修复内。
请用支持 VK_EXT_shader_float8 的当前 x86 验证层，不要用旧 SDK 1.3.296。

VK_LAYER_ENABLES is a deprecated but retained compatibility setting in current
layers; VK_LAYER_VALIDATE_SYNC is the current setting. No program rebuild is
needed. The layer must be installed/registered for x86, not just x64. A failure
such as VK_ERROR_LAYER_NOT_PRESENT is a setup failure, not a game result.
Validation output goes to the configured file, separately from dlssnr-amd.log.
If no validation output appears, verify the layer is loaded and its Log Message
action is enabled in vkconfig; no output is not proof of a clean validation run.
Capture dlssnr-amd.log too and report whether the 3D scene went black. Validation
changes timing and cannot prove absence of driver bugs or imported shader OOB.
Close this cmd window after testing to discard its environment overrides.

验证需单独运行阶段 0，不要使用阶段循环脚本。安装包含 x86 验证层的当前
Vulkan SDK，用 vkconfig 为 Game.exe 开启 Khronos 验证层、核心验证和同步
验证，把 Debug Action 设为 Log Message，并指定可写的绝对日志路径。
也可以关闭 vkconfig 覆盖后，在游戏目录的 cmd.exe 执行上面的环境变量命令。
验证日志写入 C:\NRLogs\blackgate-validation.txt，与 dlssnr-amd.log 分开。
仅装 x64 验证层不够；出现 LAYER_NOT_PRESENT 说明配置失败。没有输出也不等于
没有错误，先确认验证层已加载、日志动作已开启。请同时提供 NR 日志和是否
黑屏的结果。验证会改变时序，不能排除驱动或导入着色器的所有问题。测试后
关闭 cmd 窗口或移除 vkconfig 覆盖。
