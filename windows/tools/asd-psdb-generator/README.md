# mochi-0082-psdb-generator

Offline PSDB/SODB generator for the D3D12 ASD (ACO machine code) path, extracted
from `amd-d3d12-aco-lab` at `5c50bd2` (`--m5-build`). Windows x64, CPU only: it
never creates a D3D12 device, queue or PSO. It compiles one carrier shader per
ACO record with the official Microsoft ASD compiler runtime + AMD compiler
plugin, wraps the release's ACO body into the official ELF/metadata template, and
stores the result into a `ID3D12CompilerCacheSession` database (PSDB) plus a
`ID3D12StateObjectDatabase` (SODB). At runtime the ASI registers those files
through public D3DSCR and creates ordinary compute PSOs.

Deliverable 1: this source package (buildable anywhere with MSVC + the two
vendored-by-you binaries). Deliverable 2: the 0.0.8.2 databases under
`artifacts/0082/`, generated by exactly this source.

## Layout

```
src/asd_probe.cpp      entry: --m2-manifest, --m2-build, --canary-seed, --m5-build, --verify
src/m2.hpp             manifest (SPIR-V FNV join, reflection) + per-record PSDB build
src/m5.hpp             final databases: canary group + every record + net-carriers.bin
src/canary.hpp         rebuilds the g_pbptr canary seed from source (no machine history)
src/verify.hpp         reopens SODB/PSDB and writes a canonical content dump
src/model_elf.hpp      NRPAL001/2 record parse, ELF .text/.note retarget (M2 wrapper)
src/pbptr_elf.hpp      ELF parser + g_pbptr entry prefix (canary body)
src/spv_reflect.hpp    SPIR-V reflection: LocalSize, set-0 bindings, FNV lookup
src/common.hpp         args, app identity, PSO stream layout
src/compiler.hpp       dxc.exe invocation, root signature serialization
src/genenv.hpp         toolchain paths, compiler target/ABI selection, evidence
src/util.hpp           files, FNV/SHA-256, JSON writer
shaders/hlsl/          model_carrier.hlsl (per-record), pbptr_abi.hlsl (canary)
canary/                gfx1201_g_pbptr.bin, 424 bytes, sha256 fb081569...
scripts/build.cmd      MSVC build; path discovery overridable through env vars
scripts/generate.ps1   manifest -> canary seed -> databases -> verify
docs/CONTRACT.md       CLI, file formats, integrity-check semantics
docs/0082-REPORT.md    the 0.0.8.2 run: inputs, outputs, hashes, record diff
THIRD-PARTY.md         the two DLLs and dxc.exe: versions, acquisition, licenses
```

Not included on purpose (audited out of the lab tree): driver hooks
(`umd_elf_watch.hpp`), the in-game probe (`m1_ingame_probe`), the D3D12 device
harness/GPU sweeps (`main.cpp`, `--m2-execute`, model-prefix tools), the M4 graph
executor, and every reference/CPU-comparison binary. `--m5-build` needs none of
them.

## Requirements

- Windows x64. MSVC 19.44+ (`/std:c++17`), Windows SDK 10.0.26100.
- Agility SDK **Microsoft.Direct3D.D3D12 1.619.5** (`build/native`): headers
  (`include/d3d12compiler.h`) and `bin/x64/D3D12StateObjectCompiler.dll`,
  `bin/x64/D3D12Core.dll`.
- AMD ASD compiler plugin **amd.asdcompilerplugin 32.0.32015.7029**
  (`amdxc_compiler.dll`).
- `dxc.exe` from the Windows SDK (`10.0.26100.0` used for the 0082 artifacts).
- The ACO database access (`ID3D12StateObjectDatabase`, compiler cache sessions)
  comes from the Agility runtime, not the in-box `d3d12.dll`. The exe exports
  `D3D12SDKVersion = 619` / `D3D12SDKPath = ".\\"`, so **`D3D12Core.dll` must sit
  next to `asd_psdb_gen.exe`**. `scripts/build.cmd` copies it from the SDK when
  present.

None of these binaries are in this package. `THIRD-PARTY.md` lists exact
versions, sources and the license position.

## Build

```
set ASD_SDK_DIR=C:\path\to\microsoft.direct3d.d3d12.1.619.5\build\native
set ASD_PLUGIN_DIR=C:\path\to\amd.asdcompilerplugin.32.0.32015.7029\build\native\bin\x64
scripts\build.cmd
```

Optional overrides: `ASD_DXC`, `ASD_VCVARS` (vcvars64.bat / vcvarsall.bat),
`ASD_OBJ_DIR`. Defaults for the two SDK dirs are
`third_party\agility\build\native` and
`third_party\amd-plugin\build\native\bin\x64`, so unpacking the two NuGet
packages there needs no environment variables.

## Generate

```
scripts\generate.ps1 -Out C:\out\0082 `
  -AcoRoot  <release>\dlssnr-amd\aco `
  -ReleaseRoot <release>\dlssnr-amd
```

The script runs, in order (each step exits non-zero on failure):

```
asd_psdb_gen --root <pkg> --out <out> --m2-manifest --aco-root ... --release-root ...
asd_psdb_gen --root <pkg> --out <out>\canary --canary-seed
asd_psdb_gen --root <pkg> --out <out> --m5-build --manifest <out>\manifest.tsv
             --aco-root ... --release-root ... --canary-sodb <out>\canary\canary.sodb
             --canary-psdb <out>\canary\canary.psdb
asd_psdb_gen --root <pkg> --out <out>\verify --verify --manifest <out>\manifest.tsv
             --sodb <out>\carrier.sodb --psdb <out>\public-copy.psdb
             --carriers <out>\net-carriers.bin
```

Toolchain paths can be given to every step: `--compiler-dir DIR`,
`--plugin amdxc_compiler.dll`, `--shaders DIR`, `--dxc dxc.exe`,
`--family gfx1201` (substring of the adapter family name). Without `--root`
defaults, pass all four explicitly.

## Inputs and outputs

Inputs: the release's `aco/shaders`, `aco/int4/shaders`,
`experimental/shaders` (SPIR-V, FNV-matched to records), `aco/records`,
`aco/int4/records` (NRPAL001), the canary ACO body, and the three toolchain
binaries. `aco/rdna3` (gfx11) is deliberately **not** read: the manifest only
walks `records` and `int4/records`.

Outputs:

| file | consumer | meaning |
|---|---|---|
| `manifest.tsv` / `manifest.json` | generator | record ↔ SPIR-V join, dims, bindings, per-record flags |
| `carrier.sodb` | D3DSCR registration | one stored PSO desc per group (`g_pbptr`, `m2-<tag>`) |
| `public-copy.psdb` | D3DSCR registration | per-group value keys + wrapped ACO ELF + metadata |
| `net-carriers.bin` | ASI | root signature, and per record tag/dims/stem/src/carrier DXIL |
| `native.psdb` | intermediate | the official compiler's own template values |
| `canary/canary.sodb`, `canary/canary.psdb` | intermediate | g_pbptr seed, rebuilt from source |
| `build.jsonl`, `m5-build.json`, `verify/canonical.jsonl` | evidence | keys, SHA-256, compiler family/ABI, canonical content |

The ASI must use `carrier.sodb`, `public-copy.psdb` and `net-carriers.bin` from
the **same** run. Tags are positional over the sorted record set, so a record
added or replaced renumbers later records (and therefore their `m2-<tag>` group
key and carrier DXIL). Mixing files from two releases breaks lookups.

## Reproducibility

- `carrier.sodb` and `net-carriers.bin` are byte-identical across runs.
- `public-copy.psdb` file bytes are **not** stable (database header/ephemeral
  pages). `--verify` reopens both databases, walks every group, and writes
  `verify/canonical.jsonl` (group, key SHA-256, object-code SHA-256, metadata
  SHA-256). Two builds with equal `canonical_sha256` hold the same content.
- The canary seed is independent of any existing database: `--canary-seed`
  compiles `pbptr_abi.hlsl`, wraps `canary/gfx1201_g_pbptr.bin`, and yields the
  same key (`77894a6e...`) and ACO ELF (`fed086c1...`) as the M1/M5 lab runs.

## Limits

- Only `root` and `int4` NRPAL001 records of the given release are wrapped; the
  `rdna3` directory (gfx11/`NRPAL002`) has no compiler target here.
- CPU only: no execution, no GPU validation. Verifying the ACO machine code runs
  belongs to the runtime/ASI test, not this tool.
- App identity (`--app-exe`, `--app-name`, `--app-version`, `--app-engine`,
  `--app-engine-version`) is stored in the SODB and the cache sessions. Defaults
  reproduce the lab probe identity; they must match the registration the ASI
  performs if the runtime compares them (M1 hit with matching identity).
